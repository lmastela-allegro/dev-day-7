Komponenty interaktywne

Najpierw natywny HTML. ARIA dodaj dopiero wtedy, gdy HTML nie wystarcza, i obsłuż przy tym klawiaturę.

Przycisk

Kryteria 2.1.1 · A, 4.1.2 · A

✗ Źle: <div onclick> i ikona bez nazwy

Dodaj 🗑

✓ Dobrze: <button> z nazwą dostępną

<!-- ✗ --> <div class="btn" onclick="del()">🗑</div>
<!-- ✓ --> <button type="button" aria-label="Usuń"><span aria-hidden="true">🗑</span></button>

<button> dostaje za darmo fokus, obsługę Enter i Spacji oraz rolę „przycisk”. Ikona bez etykiety zostanie odczytana jako „kosz na śmieci” albo w ogóle pominięta.

Okno modalne

Kryteria 2.1.2 · A, 2.4.3 · A, 4.1.2 · A

✗ Źle: <div> nakładka

Newsletter

Zapisz się, aby otrzymywać nowości.

Zapisz

✓ Dobrze: natywny <dialog>

Newsletter

Zapisz się, aby otrzymywać nowości.

 
<dialog id="dlg" aria-labelledby="dlg-title">
  <h3 id="dlg-title">Newsletter</h3> …
</dialog>

openBtn.onclick = () => dlg.showModal();          // fokus wchodzi do okna, tło jest inert, Esc zamyka
dlg.addEventListener('close', () => openBtn.focus()); // powrót fokusu

Otwórz zły modal klawiaturą. Fokus zostaje na przycisku pod spodem, Tab chodzi po stronie za nakładką, a Esc nie działa. Aby go zamknąć, przejdź Tab do przycisku „Zamknij”.

W dobrym modalu fokus trafia do okna, tło jest niedostępne, Esc zamyka okno, a fokus wraca na przycisk otwierający.

Komunikaty o stanie

Kryterium 4.1.3 · AA

✗ Źle: zwykły tekst

✓ Dobrze: role="status"

Z włączonym czytnikiem ekranu kliknij oba przyciski. Tylko po prawej usłyszysz „Dodano do koszyka”. Region role="status" (aria-live="polite") musi istnieć w DOM przed zmianą treści.
